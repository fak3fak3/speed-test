# speed-test

[![tests](https://github.com/fak3fak3/speed-test/actions/workflows/tests.yml/badge.svg)](https://github.com/fak3fak3/speed-test/actions/workflows/tests.yml)

Консольный скрипт для замера скорости скачивания. Делает несколько запросов к адресу **по очереди**, каждый раз дожидаясь полного ответа, и печатает:

- время и скорость каждого запроса;
- среднее время запроса;
- общий объём скачанных данных;
- итоговую скорость скачивания в **Мбит/с** (и в МБ/с для наглядности).

## Запуск

Нужен **Python 3.9 или новее**. Внешних зависимостей нет, поэтому не нужны ни `pip install`, ни виртуальное окружение.

1. Скачай репозиторий:

   ```bash
   git clone https://github.com/fak3fak3/speed-test.git
   cd speed-test
   ```

2. Проверь версию Python:

   ```bash
   python3 --version
   ```

3. Запусти замер, передав адрес тяжёлого файла:

   ```bash
   python3 speedtest.py https://proof.ovh.net/files/10Mb.dat
   ```

Ещё примеры:

```bash
# 5 запросов вместо 10
python3 speedtest.py https://proof.ovh.net/files/10Mb.dat -n 5

# таймаут 10 секунд вместо 30
python3 speedtest.py https://proof.ovh.net/files/10Mb.dat --timeout 10

# справка
python3 speedtest.py --help
```

На Windows вместо `python3` обычно пишут `python` или `py`.

## Параметры

| Параметр | Обязательный | По умолчанию | Описание |
|---|---|---|---|
| `url` | да | — | Адрес вида `http://...` или `https://...` |
| `-n`, `--count` | нет | `10` | Сколько запросов сделать, целое число ≥ 1 |
| `-t`, `--timeout` | нет | `30` | Таймаут в секундах, число > 0 (подробнее в разделе [Таймаут](#таймаут)) |

Если параметр не передан, берётся значение по умолчанию. Неверные значения (`-n 0`, `--timeout -1`, адрес с `ftp://` или без схемы) отклоняются ещё до первого запроса.

## Вывод и коды выхода

Пример:

```
Адрес: https://proof.ovh.net/files/10Mb.dat
Запросов: 3, таймаут: 30 с

[1/3]    8.459 с      10.49 МБ       9.92 Мбит/с
[2/3]   10.297 с      10.49 МБ       8.15 Мбит/с
[3/3]    6.238 с      10.49 МБ      13.45 Мбит/с

Итог
  Успешных запросов:     3 из 3
  Среднее время запроса: 8.331 с
  Скачано всего:         31.46 МБ
  Скорость скачивания:   10.07 Мбит/с (1.26 МБ/с)
```

Неудачный запрос печатается строкой ошибки, например `[2/10] ошибка: HTTP 404 Not Found`, и замер идёт дальше.

| Код выхода | Когда |
|---|---|
| `0` | Хотя бы один запрос прошёл успешно |
| `1` | Все запросы завершились ошибкой |
| `2` | Неверные аргументы командной строки |
| `130` | Замер прерван через Ctrl+C |

Благодаря кодам выхода скрипт удобно вызывать из других скриптов и CI.

## Единицы измерения

| Величина | Единица | Определение |
|---|---|---|
| Скорость (основная) | **Мбит/с** | 1 Мбит = 1 000 000 бит |
| Скорость (дополнительно) | МБ/с | Мбит/с ÷ 8 |
| Объём | МБ | 1 МБ = 1 000 000 байт (десятичный, не MiB) |
| Время | секунды | — |

**Почему Мбит/с.** В этих единицах провайдеры указывают тарифы, а speedtest-сервисы показывают результат, так что число из скрипта можно сразу сравнить с ними. МБ/с выводятся рядом: так проще понять, сколько мегабайт файла скачивается за секунду.

**Почему десятичные приставки.** Скорости каналов всегда считают в десятичных единицах (10⁶). Если мешать их с двоичными (2²⁰), результат искажается почти на 5%.

## Технические решения

### Python и только стандартная библиотека

HTTP-запросы делает `urllib.request`, аргументы разбирает `argparse`, время измеряет `time.perf_counter`. Сторонние библиотеки (`requests`, `httpx`) задаче почти ничего не дают, а установка зависимостей усложнила бы запуск. Сейчас достаточно одного файла и установленного Python.

### Что считается временем запроса

Время — **от отправки запроса до получения последнего байта тела ответа**. Его измеряет `time.perf_counter()`: это монотонные часы с высоким разрешением, на них не влияет перевод системного времени.

Каждый запрос открывает **новое соединение**. Поэтому в его время входят DNS-запрос, установка TCP- и TLS-соединения, переход по редиректам, ожидание первого байта и само скачивание. Так ведут себя независимые обращения к ресурсу. Для больших файлов (от нескольких мегабайт) эти накладные расходы почти не влияют на результат. Для маленьких они заметно занижают скорость: подробнее в разделе [Ограничения](#ограничения).

### Последовательные запросы и полное чтение ответа

Запросы идут строго один за другим в обычном цикле, без потоков и асинхронности. Следующий запрос начинается только после того, как предыдущий ответ прочитан до конца и соединение закрыто. Тесты проверяют это отдельно (см. [Тесты](#тесты)).

### Формула скорости

```
скорость (Мбит/с) = общий объём (байт) × 8 / суммарное время успешных запросов (с) / 1 000 000
```

Скорость считается по общему объёму и общему времени, а **не как среднее скоростей** отдельных запросов. Среднее скоростей завышает результат, когда запросы шли с разной скоростью. Пример: 1 МБ за 1 с и 1 МБ за 3 с. Среднее скоростей — 5,33 Мбит/с, а на самом деле 2 МБ скачаны за 4 с, то есть 4 Мбит/с.

**Среднее время запроса** — суммарное время успешных запросов, делённое на их количество.

### Честный подсчёт байт

- **Сжатие отключено.** Скрипт отправляет `Accept-Encoding: identity`. Иначе сервер мог бы прислать сжатые данные, и неясно было бы, что именно считать.
- **Считаются только байты тела ответа**, фактически полученные из сокета. Заголовки HTTP и служебный трафик TCP/TLS не учитываются.
- **Кэш.** Скрипт отправляет `Cache-Control: no-cache` и `Pragma: no-cache`, чтобы промежуточные кэши не отдавали сохранённую копию.

### Чтение кусками

Ответ читается блоками по 64 КБ. Каждый блок учитывается и сразу отбрасывается, в памяти он не хранится. Поэтому можно замерять скачивание файлов в гигабайты: расход памяти не зависит от размера файла.

### Обработка ошибок

Один неудачный запрос не должен портить весь замер. Если запрос упал (HTTP 4xx/5xx, таймаут, отказ в соединении, обрыв посреди ответа), скрипт:

1. печатает причину в строке этого запроса;
2. считает запрос неудачным;
3. переходит к следующему.

В итог входят только успешные запросы, а строка «Успешных запросов: N из M» показывает, сколько было ошибок. Если не прошёл ни один запрос, скорость не считается и скрипт завершается с кодом `1`.

### Таймаут

`--timeout` ограничивает **каждую сетевую операцию** (подключение, ожидание очередной порции данных), а **не весь запрос целиком**. Так работает таймаут сокета в `urllib`. Медленная, но живая загрузка большого файла не оборвётся, даже если идёт дольше таймаута. А зависший сервер, который перестал присылать данные, будет обнаружен.

### Редиректы

Переходы по редиректам (301, 302, 307 и другие) выполняются автоматически. Их время входит во время запроса: так оно точнее отражает, сколько реально длится скачивание по этому адресу.

## Тесты

### Локальный запуск

```bash
python3 -m unittest discover -s tests -v
```

Тесты написаны на стандартном `unittest`, поэтому тоже ничего не требуют устанавливать. Они поднимают **локальный HTTP-сервер** на свободном порту в отдельном потоке и стучатся в него. Интернет не нужен, результат не зависит от внешних сайтов.

### Что проверяется

| Что | Как |
|---|---|
| Запросы идут последовательно и каждый ждёт полного ответа | Сервер отдаёт тело в две части с паузой и запоминает момент *перед* отправкой второй части. Тест проверяет, что каждый следующий запрос пришёл позже этого момента у предыдущего. Клиент не может получить конец ответа раньше, чем сервер начал его отправлять, поэтому проверка надёжна и не зависит от скорости машины |
| Формула скорости и среднего времени | Расчёт на заранее известных числах, включая пример, где среднее скоростей дало бы другой результат |
| Подсчёт байт | Скачанный объём сверяется с точным размером тела ответа |
| Заголовки запроса | Сервер записывает полученные заголовки, тест проверяет `Accept-Encoding: identity` и `Cache-Control: no-cache` |
| Редиректы | Запрос на адрес с 302 доходит до файла |
| Ошибки | 404, чередование 500 и 200, таймаут, закрытый порт |
| Командная строка | Значения по умолчанию (10 запросов, таймаут 30 с), флаг `-n`, коды выхода, отказ на неверных аргументах |
| Запуск как скрипта | `speedtest.py` запускается отдельным процессом, проверяется его вывод |

### GitHub Actions

Workflow [.github/workflows/tests.yml](.github/workflows/tests.yml) запускает тесты на каждый push и pull request:

- Ubuntu — Python 3.9, 3.10, 3.11, 3.12, 3.13 (минимальная и все актуальные версии);
- macOS и Windows — Python 3.13 (проверка, что скрипт и вывод кириллицы работают на всех платформах).

Результаты — на вкладке **Actions** репозитория, статус последнего прогона — на бейдже в начале этого файла.

## Ограничения

- **Маленькие файлы занижают скорость.** На файле в несколько килобайт почти всё время уходит на установку соединения, а не на передачу данных. Для осмысленного результата берите файлы от нескольких мегабайт.
- **CDN и кэши.** `Cache-Control: no-cache` — лишь просьба, и CDN может её проигнорировать. Тогда замер покажет скорость до ближайшего узла CDN, а не до исходного сервера.
- **Один поток.** Скрипт измеряет скорость одного соединения. Speedtest-сервисы обычно качают в несколько потоков параллельно, поэтому на быстрых каналах могут показывать больше.
- **Только HTTP и HTTPS.** Другие протоколы не поддерживаются.
